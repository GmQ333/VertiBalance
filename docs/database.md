# 数据库层说明

## 当前架构

平台使用 SQLite WAL 作为单实例关系型存储，默认文件为 `data/vertibalance.sqlite`。运行路径可通过服务端环境变量 `DATABASE_PATH` 修改。

数据库包含用户、科室、问诊、消息、独立风险评估、报告、排班、挂号、处置、随访、通知、上传元数据、反馈、危险规则、知识库、模型配置、模型调用和审计日志表。业务关联使用外键，账号、模型版本、报告和挂号等关键不变量由数据库唯一约束兜底。

## 迁移

启动时按文件名顺序执行 `server/migrations/*.sql`，成功后写入 `schema_migrations`。迁移和版本记录位于同一事务中，禁止直接修改已应用的迁移文件。

如果新数据库旁存在旧版 `data/vertibalance.json`，首次启动会将其完整导入关系表。SQLite 初始化成功后，JSON 不再参与读写。

## 事务

写操作使用 `BEGIN IMMEDIATE`。每个接口只加载和提交自身涉及的业务集合，多实体状态变化与审计记录在同一事务中完成。大模型和模型连通性请求在事务外执行。

SQLite 约束失败会回滚整个业务事务。数据库使用 `foreign_keys=ON`、`synchronous=FULL`、WAL 和写入忙等待。

## 审计

审计表禁止更新和删除。每条审计记录保存前一条记录哈希和自身 SHA-256 哈希；服务启动时验证完整链条，发现离线修改会拒绝启动。

## 文件

患者上传文件不放入数据库，只在数据库保存受控元数据。文件使用随机存储名和 `0600` 权限，上传时同时检查声明 MIME 和文件签名。若元数据事务失败，已写文件会立即清理。

## 备份

`npm run db:backup` 使用 SQLite `VACUUM INTO` 生成一致性数据库副本，同时复制上传目录并生成 SHA-256 清单。备份生成后会立即执行数据库完整性和文件校验。`npm run db:restore` 仅允许恢复到不存在的新目标，恢复前验证全部校验和，避免误覆盖当前生产数据。

生产环境仍需配置异机加密备份、保留周期、监控告警和定期恢复演练。SQLite 适用于当前单实例阶段；扩展为多实例高可用部署前，应按相同仓储边界迁移到 PostgreSQL。
